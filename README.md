# AI Workbench · 多模型统一工作台

把 **Codex、Claude Code、千问 Qwen Code、DeepSeek Harness、WorkBuddy/CodeBuddy、Kimi、豆包、Ollama 本地模型** 装进同一个界面里使用：界面参考 Codex，左边是对话列表，右边是聊天区，随时可以换引擎、换模型、看原始日志。

它是**零依赖**的：只用 Node 自带的模块，不需要 `npm install`，没有构建步骤，断网也能启动。

## 安装（从源码）

需要 **Node.js 22+**（用到内置的 zstd / fetch）。

```powershell
git clone <你的仓库地址> ai-workbench
cd ai-workbench
node tools/setup.mjs      # 可选：自动探测本机装了哪些 CLI
node server/index.mjs     # 启动，打开 http://127.0.0.1:4317
```

Windows 下也可以直接双击 `start.cmd`（会自动挑端口、等服务就绪再开浏览器）。

首次运行时，如果 `config/engines.json` 不存在，会自动用 `config/engines.example.json` 生成一份；那个文件是**个人配置**（含本机路径），已经在 `.gitignore` 里，不会被提交。

`node tools/setup.mjs` 会扫描 PATH 和 npm 全局目录，把 `codex` / `claude` / `qwen` / `dsh` 等命令解析成真实入口写进配置；已有的路径不会被覆盖。

## 快速开始

**双击桌面上的「AI Workbench」快捷方式**，或者在项目目录执行：

```powershell
node server/index.mjs
```

快捷方式会自动判断服务是否已经在跑：没跑就启动并自动打开浏览器，已经在跑就直接打开浏览器，不会重复起服务。界面地址是 **http://127.0.0.1:4317**，关掉那个黑窗口（或者 Ctrl+C）就退出工作台。

> 换端口：`$env:PORT=5000; node server/index.mjs`

桌面快捷方式指向 `start.cmd`，用的是项目自己的图标。图标是脚本生成的，想换配色改 `tools/make-icon.mjs` 里的几个色值，然后：

```powershell
node tools/make-icon.mjs    # 重新生成 assets\aiworkbench.ico 和预览图
```

## 怎么用

**选引擎开始对话。** 打开页面就是引擎选择面板，点哪个引擎就用哪个引擎开新对话。顶栏的三个胶囊分别是「引擎 / 模型 / 工作目录」，随时可点开切换；切换后下一条消息就由新引擎回答，历史记录保留在同一个对话里。

**对话会记住。** 每个对话都落盘到 `data/conversations/`，关掉再开还在。给 CLI 引擎发消息时，工作台会把最近的对话轮次和「长期记忆」一起拼进提示词；如果这个 CLI 支持原生续聊（Codex 的 `exec resume`、Claude 的 `--resume` 等），则改用原生的会话 ID 续接，避免重复喂上下文。

**记忆。** 「设置 → 记忆」里可以写全局记忆（每次对话都会带上），也可以攒一条条带标签的记忆条目。

**导入对话。** 「导入」按钮里三个来源：

- **本机 CLI 历史** —— 扫描这些目录，勾选即可导入；Codex 的环境上下文、技能说明等包装内容会自动剥掉，只留真正的对话。解析不出真实消息的文件会被跳过，不会导入一堆垃圾会话。

  | 来源 | 目录 | 说明 |
  | --- | --- | --- |
  | Codex | `~/.codex/sessions` | 当前会话，标题优先取 `session_index.jsonl` 里你自己起的名字 |
  | Codex 桌面版（归档） | `~/.codex/archived_sessions` | 桌面版归档的历史会话，容易漏掉，默认也会同步 |
  | Claude Code | `~/.claude/projects` | 子代理记录（`isSidechain`）会被排除 |
  | DeepSeek Harness | `~/.dsh/sessions` | `session.jsonl.zstd` 是**多帧** zstd，会逐帧解压 |
  | Qwen Code | `~/.qwen/projects` | 目前只存进程运行时元数据，扫不到内容属正常 |
- **从文件导入** —— OpenAI / Claude 导出的 JSON、JSONL，以及 Markdown、纯文本。
- **粘贴导入** —— 直接把一段对话贴进来。

在你这台机器上实测的扫描结果：Codex 13 个会话、Claude Code 4 个会话可直接导入；Qwen Code 的 `~/.qwen` 里只有进程运行时元数据（没有可读对话），CodeBuddy 还没产生过会话，dsh 的 3 个会话都是空会话 —— 这些都正常显示为 0，不会报错。

**自动同步。** 左下角的胶囊点一下就能开关。开启后服务端按固定间隔扫描历史目录，**只处理新增或被改动的文件**（比对 mtime + size），导入过的文件不会重复导入，之后原 CLI 里新增的会话会自动出现在工作台，界面会收到实时提醒。

**默认就是开着的**（每 20 秒一轮，默认同步 Codex 和 Claude Code）。导入一批之后，侧栏会立刻刷新，顶栏的「已同步 · 3 分钟前 · 新导入 4」就是同步状态；后台同步过但界面没反应这种情况不会发生。方向是 **CLI → 工作台**：你在 Codex / Claude Code 里聊的内容会自动进工作台；工作台自己发起的对话存在 `data/conversations/`，不会反向写回各家的 CLI 数据库。

Codex 内部的子代理会话（比如审批裁判 `thread_source: "subagent"`）和 Claude Code 的子代理记录（`isSidechain`）会被自动排除，不会污染你的对话列表。

## 删除对话

侧栏每条对话右侧都有一个 **✕ 按钮**，点一下立刻删除——**没有任何确认弹窗**。

删除会做三件事：

1. **从工作台移除**，会话列表立刻刷新。
2. **记下删除记录**（`data/imported/ignored.json`），之后自动同步不会再把它拉回来。记录同时按**文件路径**和**会话 ID** 记，所以就算源软件把这条会话从 `sessions/` 挪进 `archived_sessions/` 换了名字，也不会复活。
3. **同步给源软件**：把 Codex / Claude Code / dsh 里对应的记录也移走。不是硬删除——文件被移到 `data/trash/<时间戳>/...`，所以源软件里看不到了，但随时能找回来。

删除后右下角的提示里有 **「撤回」** 按钮，点一下文件回原位、会话也重新导入。想彻底清掉回收站，直接删 `data/trash` 目录即可。

两个安全设计：

- **CLI 还在写的会话不动源文件**。如果那条会话最近 2 分钟被写过（比如就是你正在用的这条对话），只删工作台的副本，源文件保留，避免弄坏正在进行的会话；提示里会说明。
- 想只在工作台里删、不动源软件，去「设置 → 翻译 & 容错」关掉「删除导入的对话时，同时从源软件移除」。

**删除顺序是故意的**：先写删除记录，写不进去就干脆不删（会明确报错）。只有记录落盘成功之后，才会真的删会话、再去动源文件。所以哪怕源文件移除失败、或者你关掉了「同时从源软件移除」，下次同步也**不会**把它拉回来——自检里有一条专门验证这个：源文件留在原地、之后还被追加了内容，仍然不会复活。

早期的删除记录只记了文件路径，源文件一改名就会失效。补了一个维护脚本，从 `data/trash` 的备份（或源目录里还在的原件）读出会话 ID 回填进去：

```powershell
node tools/backfill-tombstones.mjs
```

**新建文件夹。** 选工作目录时（顶栏的目录胶囊，或设置里的「浏览…」），左下角有「＋ 新建文件夹」——直接在当前目录下建一个新文件夹并切进去，再点「使用这个目录」就行。名称里的 `\ / : * ? " < > |` 会被拦下来，重名会提示而不是覆盖。

**本地程序。** 首页底部和左侧「本地程序」都能一键启动本机的 exe（Ollama、豆包、Claude、WorkBuddy 桌面版）。自己的程序在「设置 → 本地程序」里填路径加进来即可，比如千问桌面版、Kimi、Cherry Studio。

**运行日志。** 右上角 `▤` 打开右侧抽屉，能看到实际执行的命令行、原始 JSON 事件、stderr 和时间信息。引擎输出格式对不上时，先看这里最快。

**一边生成一边干别的。** 生成任务跟着**对话**走，不跟着界面走：回答到一半切到别的对话，它照常在后台跑；切回来还能看到实时输出。侧栏那条会显示「生成中…」，顶栏也会显示有几个对话在跑。你也可以在另一个对话里直接发新消息，互不影响；想停下来点「停止」。

## 翻译对话

任何一条消息都能翻译，整个对话也能一次翻完，译文直接挂在原文下面（刷新、重启都还在）。

- **单条**：鼠标移到消息上，点「翻译」。
- **整段**：右键侧栏里的对话 →「翻译整个对话」，只翻还没译过的，单次最多 40 条。
- 弹窗里选目标语言（简繁英日韩俄西）、翻译引擎和模型。
- 默认走**本机 Ollama**：免费、不消耗额度。模型默认**自动挑参数量最小的那个**——纯 CPU 上 14B 会比 7B 慢好几倍，翻译没必要用大模型。单条超过 90 秒自动跳过，不会卡住整批。
- 译文块上有「重新翻译 / 删除译文 / 复制 / 收起」。

实测：93 个字的消息用 qwen2.5:7b 约 10 秒；1143 个字约 90 秒（纯 CPU 的代价，有 GPU 会快很多）。

## 用之前先体检

## 环境变量：CLI 能不能用，八成看这里

命令行引擎（Codex / Claude Code / 千问 / dsh …）是由工作台启动的，默认只继承桌面快捷方式那点环境变量。而很多人（包括这台机器）是把 API 地址、Token、代理写在 **PowerShell profile** 里的——工作台拿不到，于是「终端里能用，工作台里报未登录 / 未知错误」。

工作台现在把这件事接管了：

1. 启动时跑一次带 profile 的 PowerShell，把整套环境抓回来。
2. **同时直接读 profile 文件**里的 `$env:XXX = "值"`——因为很多机器的执行策略是 Restricted，profile 根本不会被执行（启动时报「禁止运行脚本」），但里面的配置照样能读出来。
3. Claude Code 自己的 `~/.claude/settings.json` 里如果写了 `env`，也一并算上。
4. 优先级：系统/进程环境 < profile < Claude settings < 设置里手填的「额外环境变量」< 引擎配置里的 `env`。

「设置 → 环境变量」里能看到当前解析出来的关键变量（密钥会打码）、来源文件和数量，改完 profile 点「重新同步」即可；也可以在下面手填 `KEY=VALUE` 覆盖。

顺便：Codex 会同时被注入 `CODEX_HOME=~/.codex`。不然它有时会解析不出 home 目录，直接报 `Could not find home directory` 然后什么都不干。

### Claude Code 有个特别的坑

Claude Code 会读 `~/.claude/settings.json` 里的 `env` 块，而且**优先级高于进程环境变量**——如果那里写着一个失效的 token，无论工作台注入什么都会被它盖掉（`--settings` 是唯一能压过它的东西）。

所以工作台会：把解析好的环境写成 `data/claude-settings.json`，再用 `--settings` 传给 Claude Code。这样你**不用改自己的配置文件**，工作台里就能用正确的 token。实测报错从 `API Error: 401 ... api key is invalid` 变成正常出结果。

另外 workspace 里所有的引擎进程都是由工作台启动的：**如果工作台是在受限环境里启动的**（比如被某个沙箱包着），它启动的 Codex / Claude 也会继承那些限制，表现为「连不上 API」「拒绝访问 ~/.codex」。用桌面快捷方式正常启动就没这个问题。

## 模型列表是动态读的

不再写死模型名——每个引擎按自己的真实配置来：

| 引擎 | 模型从哪来 |
| --- | --- |
| Codex | `~/.codex/models.json`（模型目录）+ `~/.codex/config.toml` 里的当前模型 |
| Claude Code | `~/.claude/settings.json` / profile 里的 `ANTHROPIC_MODEL`、`ANTHROPIC_DEFAULT_*_MODEL` |
| Ollama | 实时问 `127.0.0.1:11434/api/tags`，新拉的模型自动出现 |
| DeepSeek / Kimi / 千问 / 豆包 / 任意 OpenAI 兼容 | 带上你的 Key 去问接口的 `/models` |

拿不到网络时就退回配置里的兜底列表。另外还有一个自愈逻辑：如果某个对话记着的模型在当前引擎的可用列表里已经不存在了（比如换了 provider），这次会自动改用引擎默认模型，并在日志里说明，而不是把错误抛给你。

引擎不是「点下去才知道能不能用」——发消息之前工作台会先检查一遍：命令行程序在不在、入口文件在不在、**真跑一次 `<cmd> --version` 确认能启动**、云端接口有没有 Key、服务连不连得上。

- 检查结果会显示在顶栏引擎胶囊上（绿点可用 / 黄点有问题，鼠标悬停能看到具体哪一项没过）。
- 点发送时再查一次（结果缓存 30 秒，不拖慢发送）：**不合格就根本不会发出去**，弹一个面板写清楚哪几项没过，并提供「重新检测」和「换个引擎发送」。
- 开着「报错自动换模型」的话，不合格的引擎会被**直接换掉**再发出，你连报错都看不到——只在对话里留一条说明「某某用不了（原因），已改用某某」。

这样就不会再出现「点了发送，跑一半吐一堆英文错误」的情况。

## 豆包：直接调用桌面客户端

没有火山方舟的 API Key 也能用豆包——引擎列表里多了一个 **「豆包 桌面版（客户端）」**（`kind: "desktop"`）：

1. 先体检：确认豆包客户端装在哪儿。
2. 用之前先打开 / 聚焦窗口，把消息放进剪贴板并自动粘贴、回车发送。
3. **消息会留在剪贴板里**——万一自动粘贴没生效（比如窗口没抢到焦点），你按一下 Ctrl+V 再回车就行。
4. 客户端不会把回复送回来，所以对话里会多一条提示，点「📋 把回复贴回来」把答案粘进对话，之后照常回看、复制、翻译。

原来那个走官方接口的「豆包 API（火山方舟）」还在，填了 Key 就能用。

「设置 → 外观」里可以改四样东西，**改动立即生效并自动保存**，不用点保存按钮：

- **主题**：深色 / 浅色 / 跟随系统（跟着 Windows 的深浅色设置走）。
- **主题色**：9 个预设色（蓝、青、紫、粉、橙、黄、绿、天蓝、红），也可以点右边取色器选任意颜色。按钮、选中态、链接、译文标记、引擎圆点都会跟着变；文字对比度按颜色亮度自动选黑或白，不会出现看不清的情况。
- **字体**：系统默认 / 微软雅黑·苹方 / 衬线（宋体·思源宋体）/ 等宽字体（整个界面）。
- **字号**：小 / 中 / 大 / 特大，整个界面按比例缩放（不是只改某几处）。
- **导入字体**：点「＋ 导入字体文件」选本地下载的 `.ttf / .otf / .woff / .woff2`（单个上限 12MB），导入后立刻能用。字体存在 `data/fonts`，列表里每一条都能「用这个 / 删除」。换电脑时把整个 `data` 目录拷过去，字体跟着走。

面板底部有预览框，改了立刻能看效果；不满意点「恢复默认」。

主题会缓存在浏览器本地，下次打开先用缓存渲染，**浅色主题不会先闪一下黑屏**。

外观设置本身存在 `data/settings.json` 里，**关掉工作台、重启电脑都还在**（浏览器缓存只是用来避免首屏闪烁，不是唯一存储）。

整套配色收敛成了 CSS 设计变量（两套主题共 60 多个 token），所以浅色模式下不会漏出深色块——自检里有一条专门盯着这个问题：规则区一旦出现写死的颜色就会报错。

## 报错处理：自动换模型 + 匹配模型修复

引擎报错不会只丢给你一句英文错误，工作台分两步兜底。

**第一步，自动换模型接手。** 认出错误类型（登录失效 / 限流 / 网络不通 / 环境问题 / 上下文超长 / 模型名不对…）后，按「设置 → 翻译 & 容错」里的顺序找第一个真能用的模型，把你的原始请求连同错误信息一起交给它，并在对话里留下「谁失败了、换谁接手」的记录。默认顺序：Claude Code → Ollama → 千问 → WorkBuddy → 豆包 → Kimi，最多连换 2 次。

**第二步，点一下让它真正修好。** 报错那条消息上有两个按钮：

- **⇄ 用其他模型处理**：换一个模型回答你原来的问题（一次性接手）。
- **🛠 修复这个报错**：按错误类型**匹配**合适的模型去修根因——登录/环境/配置类问题交给能读写本机文件、能跑命令的 CLI agent（Codex / Claude / WorkBuddy / 千问），网络类问题优先让本机 Ollama 先排除本地因素。它拿到的是：出问题的引擎、启动参数、工作目录、工作台配置路径、运行日志目录，以及你的原始需求；提示词里明确要求「先定位根因、能修就直接修、修完必须跑命令验证、最后给出结论」。

修完之后，如果原来那个引擎恢复了，对话里会出现「↻ 用 XXX 重试」按钮，一键回到原引擎继续。

> 自动接手默认开着，自动**修复**没有默认开——修复会真的动你本机的文件和配置，所以留给你点一下再决定。

**快捷键。** `Enter` 发送，`Shift+Enter` 换行，`Ctrl+K` 搜索对话，`Ctrl+N` 新对话，`Esc` 关弹窗。对话有 URL 锚点（`#/c/<id>`），刷新后会回到同一会话。

```
AIWorkbench/
├─ start.cmd              双击启动

```

## 加一个新引擎

改 `config/engines.json` 就行，服务端按文件修改时间自动重载。

**命令行程序**（`kind: "cli"`）：

```json
{
  "id": "mytool",
  "label": "我的 CLI",
  "kind": "cli",
  "group": "本地 CLI",
  "command": "node",
  "entry": "D:\\tools\\mytool\\cli.js",
  "baseArgs": ["--print", "--output-format", "stream-json"],
  "modelFlag": ["--model", "{{model}}"],
  "cwdFlag": ["--cd", "{{cwd}}"],
  "promptMode": "arg",
  "models": ["default"],
  "resumeArgs": ["--print", "--resume", "{{sessionId}}"],
  "resumePromptMode": "arg"
}
```

- `command` + `entry`：Windows 上推荐写成「`node` + 脚本路径」，绕开 `.cmd` 的引号转义问题；也可以直接写 exe 绝对路径。
- `promptMode`：`arg` 表示提示词作为最后一个参数，`stdin` 表示写进标准输入。参数模板里写 `{{prompt}}` 可指定插入位置。
- `streamMode`：`auto` 会逐行尝试解析 JSON 并提取文本、工具调用、会话 ID；解析不出来就当纯文本处理。`text` 表示纯文本输出。
- `resumeArgs`：有它且引擎返回过会话 ID 时，工作台会自动改用原生续聊。

**HTTP 接口**（`kind: "openai"`）：任何 OpenAI 兼容服务都行，填 `baseUrl`、`models`，密钥在「设置 → API Key」里填（也可以走环境变量，见 `apiKeyEnv`）。本地服务要实时拉模型列表就加 `modelsEndpoint`。

**本地程序**（`kind: "app"`）：只填 `command` 指向 exe，界面里提供一键启动。路径支持 `~`、`%LOCALAPPDATA%` 这类写法。

## 数据与隐私

所有对话都存在本机的 `data/` 目录：

- `data/conversations/*.json` —— 对话正文，想备份直接拷这个目录
- `data/runs/*.jsonl` —— 每次运行的原始事件日志
- `data/settings.json` —— 设置与 API Key（**注意不要把这台机器的这份文件分享出去**）
- `data/memory.json` —— 长期记忆
- `data/sync-state.json` —— 自动同步进度

服务只监听 `127.0.0.1`，不会对外暴露。调用各家模型时数据会发给对应的官方接口或本机 Ollama，这一点和其它客户端一致。

## 自检

```powershell
node tools/selftest.mjs
```

会临时起一个独立实例，逐项验证：引擎探测、命令行流式通道（用内置的模拟引擎）、Ollama 真实往返、对话落盘、原生续聊、记忆注入、错误处理、历史解析与导入、增量同步、Markdown 渲染、消息编辑、前端接线。当前 16/16 通过。

## 已知限制

- **CLI 引擎要能自己登录**：工作台不接管各家 CLI 的登录状态。如果界面里提示 `Not logged in`，先在终端里用对应的 CLI 登录一次。
- **Codex 需要 HOME**：启动子进程时会自动补上 `HOME`（Windows 上有些环境只设了 `USERPROFILE`，会让 Codex 报 "Could not find home directory"）。
- **输出格式会随版本变化**：解析器是容错的（不认的字段就当纯文本），但遇到 CLI 大改版仍可能需要调 `config/engines.json` 里的参数或 `streamMode`。
- **`tools/screenshot.mjs`** 用于给界面截图，需要本机 Chrome/Edge 的 DevTools 端口可用；在受限环境里可能连不上。
- **豆包、Kimi**：目前走官方 OpenAI 兼容接口（火山方舟 / Moonshot）。桌面版 App 只能一键启动，不做界面自动化。
